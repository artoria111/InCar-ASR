# InCar-ASR 现有功能手册

## 1. 安装

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
```

仅使用 mock、评测和命令功能时只安装 NumPy。使用 ONNX Runtime：

```bash
python -m pip install -e '.[onnx]'
```

## 2. 命令总览

```text
incar-asr validate-contract
incar-asr build-catalog
incar-asr validate-manifest
incar-asr collect-device-info
incar-asr infer
incar-asr evaluate
incar-asr stream
```

运行 `incar-asr <子命令> --help` 可查看参数。

## 3. 模型契约

验证配置结构，不要求大文件存在：

```bash
incar-asr validate-contract \
  --contract configs/model_contract.example.json
```

交付或正式测试时必须加：

```bash
incar-asr validate-contract \
  --contract configs/model_contract.json \
  --require-artifacts
```

详细字段见 `docs/模型接口契约.md`。

## 4. 指令目录

生成默认目录：

```bash
incar-asr build-catalog --output artifacts/command_catalog.json
```

目录是 JSON 数组，每项包含：

```json
{
  "text": "温度调到二十六度",
  "intent": "climate.set_temperature",
  "slots": {"temperature": 26}
}
```

推理和评测可通过 `--catalog` 使用自定义目录。未提供时使用内置 283 条命令。匹配器会输出：

- `corrected_text`：命令增强后的文本。
- `intent`：意图。
- `slots`：结构化参数。
- `command_confidence`：最佳相似度。
- `command_rejected`：是否因分数或 margin 不足而拒绝。

## 5. 数据 manifest

每行一个 JSON 对象：

```json
{
  "sample_id": "TC0001",
  "clean_audio": "audio/clean/open_ac.wav",
  "noise_audio": "audio/noise/wind.wav",
  "noise_type": "wind",
  "snr_db": 5,
  "transcript": "打开空调",
  "intent": "climate.open",
  "slots": {},
  "speaker_id": "S01",
  "split": "test",
  "seed": 42
}
```

规则：

- 音频路径相对 manifest 所在目录解析，也可使用绝对路径。
- `sample_id` 必须唯一。
- 设置 `noise_audio` 时必须设置 `snr_db`。
- 同一 `speaker_id` 不允许跨 train/dev/test。
- 同一 `clean_audio` 不允许跨不同 split。
- 正式测试必须提供 `transcript`。
- 音频由程序转为后端要求的采样率。

只检查格式：

```bash
incar-asr validate-manifest \
  --manifest examples/manifest.example.jsonl \
  --allow-missing-audio
```

正式检查：

```bash
incar-asr validate-manifest --manifest /path/to/test_manifest.jsonl
```

## 6. 单条推理

### Mock 联调

```bash
incar-asr infer \
  --backend mock \
  --mock-text 打开空条 \
  --audio /path/to/audio.wav
```

### ONNX Runtime

```bash
incar-asr infer \
  --backend onnx \
  --contract configs/model_contract.json \
  --audio /path/to/audio.wav
```

### Atlas 设备 CLI

```bash
incar-asr infer \
  --backend device \
  --device-command \
  'modules/04_atlas_edge_deployment/build/car-asr-cli --model /path/model.om --tokens /path/tokens.txt --wav {wav} --json' \
  --audio /path/to/audio.wav
```

`{wav}` 是必需占位符。程序会创建临时 16 kHz PCM16 WAV，调用设备 CLI，并读取 stdout 最后一个 JSON 对象。

路径包含空格时可改用 JSON 数组：

```bash
incar-asr infer \
  --backend device \
  --device-command-json \
  '["/path/car-asr-cli","--model","/path/model.om","--tokens","/path/tokens.txt","--wav","{wav}","--json"]' \
  --audio /path/to/audio.wav
```

## 7. 批量评测

```bash
incar-asr evaluate \
  --backend onnx \
  --contract configs/model_contract.json \
  --manifest /path/to/test_manifest.jsonl \
  --output reports/onnx
```

若 manifest 有噪声音频，程序按每条数据的 `snr_db` 和 `seed` 在内存中混噪。混合结果不会默认保存，避免产生大文件。

输出：

- `results.jsonl`：逐条参考文本、原始文本、纠错文本、意图/槽位、SNR、耗时、RTF 和错误。
- `summary.json`：聚合指标。
- `report.md`：可直接阅读的表格和 bad cases。

主要指标：

- `raw.corpus_cer`：所有字编辑数除以所有参考字数。
- `command_aware.corpus_cer`：命令增强后的 CER。
- `exact_match_accuracy`：整句完全一致比例。
- `intent_accuracy`：有意图标注样本的准确率。
- `slot_micro_f1`：所有槽位键值对的 Micro-F1。
- `latency_ms`：端到端批测调用耗时。
- `rtf`：总耗时 / 音频时长，小于 1 表示快于实时。

注意：设备 CLI 返回的 `inference_ms` 是纯 NPU 推理指标；外层 `total_ms` 还包含临时 WAV、进程启动、VAD、前处理、解码等成本。

## 8. 流式 WAV 模拟

```bash
incar-asr stream \
  --backend onnx \
  --contract configs/model_contract.json \
  --audio /path/to/long_audio.wav \
  --chunk-ms 40
```

此功能将已有 WAV 按 chunk 输入流式 VAD，对每个结束的语音段调用一次后端。适合代码组验证切段，不等于实时麦克风驱动。

## 9. 设备信息采集

```bash
incar-asr collect-device-info \
  --output device_report/device_info.json \
  --artifact /path/to/model.om \
  --artifact /path/to/tokens.txt
```

记录平台、架构、Python、`npu-smi`、ATC、CMake、编译器以及指定文件大小和 SHA256。不会收集 SSH key、token 或整个环境变量。
