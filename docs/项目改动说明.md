# InCar-ASR 项目改动说明

## 1. 改动目标

原 `main` 分支主要是 Atlas C++ 推理骨架：仓库可以展示模块划分，但模型接口、数据评测、流式输入、命令理解和可复现实验尚未形成闭环。此次修改把项目提升为“代码组可开发验证、设备组可执行回传”的完整工程框架。

本次没有下载或提交任何大模型、数据集、音频和设备 profiling 文件。

## 2. 主要变化

### 2.1 新增统一模型接口契约

新增 `src/incar_asr/contracts.py` 和 `configs/model_contract*.json`：

- 固定记录采样率、输入/输出 tensor 名、形状、dtype。
- 固定记录 FBank、频谱类型、LFR、CMVN 参数。
- 固定记录解码器类型、blank id、特殊 token。
- 校验前端输出维数是否与模型输入一致。
- 可选择检查模型和 token 文件是否真实存在。

这解决了原项目中“Python 模型可能使用 560 维 LFR，而 C++ 固定假设 80 维 FBank”“Paraformer 输出与 CTC 解码混用”的核心风险。

### 2.2 新增普通电脑可运行的参考管线

新增 `src/incar_asr/audio.py`、`backends.py`：

- 依赖标准库和 NumPy 的 PCM WAV 读取、单声道转换和线性重采样。
- 80 维 log Mel FBank、LFR 堆叠、可选 CMVN。
- mock 后端用于 CI 和无模型联调。
- ONNX Runtime 后端按模型契约验证输入输出。
- Atlas CLI 子进程后端把设备程序接入同一批测框架。

代码组因此不需要等待设备，也能先把 manifest、评测、命令理解和报告逻辑跑通。

### 2.3 新增真实、可追溯的鲁棒性评测

新增 `evaluation.py`、`metrics.py`、`report.py`：

- 逐条读取 JSONL manifest。
- 在内存中按指定 SNR 动态混合干净语音和噪声，不生成大批重复 WAV。
- 记录请求 SNR 与实际达到的 SNR。
- 计算 Corpus CER、平均句级 CER、完全匹配率、意图准确率、槽位 Micro-F1。
- 计算平均/P50/P90/P95/P99 延迟及 RTF。
- 按噪声类型和 SNR 分组。
- 输出逐样本结果、JSON 汇总、Markdown 报告和 bad cases。
- 有效样本为 0 时直接失败，不能产生“空测试通过”。
- 检测重复 sample id、说话人跨集合泄漏和同一录音跨集合泄漏。

原来随机数或手写表格形式的图表不能作为实验结论；新报告只使用当次真实结果。

### 2.4 新增车载命令理解

新增 `commands.py`：

- 默认生成 283 条确定性车载命令。
- 覆盖空调、车窗、天窗、音乐、电话、导航等场景。
- 支持常见 ASR 混淆纠正，例如“打开空条”纠正为“打开空调”。
- 支持温度、风量、车窗位置、联系人、导航目的地等槽位。
- 使用置信阈值与 top-2 margin 拒绝不确定输入，避免任何文本都被强行纠正成指令。

评测同时保留原始 ASR 文本与命令增强文本，能够量化增强前后的收益。

### 2.5 新增流式 VAD

Python 新增状态化自适应能量 VAD：

- 20 ms 帧处理。
- pre-roll 防止吞掉首字。
- 连续语音启动、连续静音结束。
- 自适应噪声基线。
- 最短/最长语音保护。
- 可用 WAV 模拟分块流式输入。

C++ VAD 修复了原实现的两个严重问题：

- 删除“编译时宣称 WebRTC 可用、运行时却固定返回 false”的空实现。
- 删除函数内 `static` 噪声状态，避免不同请求和不同实例互相污染。

### 2.6 Atlas C++ 核心修复

修改 `modules/04_atlas_edge_deployment`：

- 空 PCM 不再访问 `pcm[0]`。
- 将 O(T×N²) 占位 DFT 改为 radix-2 FFT。
- FBank 使用 power spectrum，与示例契约一致。
- 删除未在契约中声明的整句标量归一化。
- 把“重复惩罚”的伪 beam search 改为 CTC prefix beam search。
- WAV 读取不再假设固定 44 字节头；遍历 RIFF chunk 并严格要求 PCM16/mono/16 kHz。
- `--vad-mode` 长参数现在真正生效。
- 新增 `--beam-size` 和 `--json`。
- `--json` 最后一行可被设备批测适配器解析。
- `RecognizeStream` 至少完成分块累积与 end-of-stream 识别，不再永远返回空。
- 修复 ASR 引擎与 ACL 对象析构时重复 `Destroy()`。
- ACL 资源释放改成按初始化状态执行。
- 初始化时拒绝当前运行时不支持的多输入、多输出和非 float32 I/O。
- 静态 OM 输入按模型缓冲区补零，过长输入会明确警告并截断。
- 输出 shape 和元素数量异常时明确失败。

### 2.7 新增测试和 CI

Python 测试覆盖：

- WAV 读写与重采样。
- 80/560 维前端。
- 指定 SNR 混噪。
- 模型契约维数检查。
- Atlas 子进程 JSON 适配。
- 指令纠错、意图和槽位。
- CER 和汇总指标。
- manifest 泄漏检测。
- 真实报告文件生成。
- 双语音段流式 VAD。
- 设备信息与 SHA256。

便携 C++ 测试覆盖：

- 空音频。
- FBank 帧数、维数和有限值。
- VAD 切段与 reset 隔离。
- CTC greedy 和 prefix beam。
- WAV 往返。

`.github/workflows/ci.yml` 在 Ubuntu 上自动运行两组测试；C++ 核心测试不依赖 CANN。

## 4. 已验证与待真机验证

已在 macOS 普通电脑验证：

- Python 源码编译。
- 全部 Python 单元测试。
- 便携 C++ 核心以 C++17、`-Wall -Wextra -Werror` 编译并运行。
- shell 脚本语法。
- 示例模型契约和缺少音频模式下的 manifest。

必须由设备组验证：

- CANN 头文件和库与实际安装版本的兼容性。
- `acl-hello` 的 NPU 链路。
- 最终 ONNX→OM 转换。
- OM 的真实输入输出 tensor、dtype 和数值一致性。
- 最终模型 CER、指令准确率、延迟、RTF、功耗和内存。
- 车内麦克风、噪声和说话距离条件下的 VAD 参数。

## 5. 当前限制

- 仓库没有最终模型、token、CMVN、测试音频，因此不声称已有准确率和设备性能结果。
- Atlas C++ 当前是“单输入 + 单输出 + float32 I/O + CTC logits + 80 维 FBank”路径。
- 示例 Paraformer ONNX 契约是另一条参考路径；若最终选 Paraformer，需为 C++ 实现对应多输入/解码逻辑或把模型导出成统一单输入单输出接口。
- C++ `RecognizeStream` 是分块收集后在结束时整句识别，不是增量模型解码。
- 麦克风采集没有绑定具体硬件 API；设备组应先录成 16 kHz mono PCM16 WAV，或后续接 ALSA。
- 能量 VAD 不是神经网络 VAD，车内参数必须实测。

## 6. 建议下一阶段

1. 模型组确定唯一模型接口，填写正式 contract，并生成 10 条 golden sample。
2. 用同一 golden sample 比较 Python ONNX 与 Atlas OM 的 token/text 输出。
3. 设备组完成 3 种噪声 × 4 个 SNR × 多说话人的测试矩阵。
4. 根据 bad cases 调整指令目录和 VAD，而不是只报告平均 CER。
5. 如最终使用 Paraformer，优先统一导出与后处理，再扩展 C++，不要继续沿用 CTC 假设。
