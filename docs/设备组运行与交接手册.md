# Atlas 设备组运行与交接手册

本文给没有参与代码开发的设备组成员使用。目标是：在 Atlas 上完成环境确认、编译、单条识别、批量测试，并把足以复现结果的文件交回代码组。

## 1. 设备组需要拿到的文件

代码仓库本身不带大文件。请从组内文件存储单独取得：

- 最终 `.om` 模型。
- 与模型完全匹配的 `tokens.txt`，每行一个 token，行号从 0 开始。
- 正式 `model_contract.json`。
- 测试 manifest、干净语音和噪声音频。
- 如果需要自行转换，还要取得原始 `.onnx`。

收到后先核对组内提供的 SHA256，不要只比较文件名。

## 2. 克隆与 Python 环境

```bash
git clone --filter=blob:none --single-branch \
  --branch agent/robust-asr-platform \
  git@github.com:artoria111/InCar-ASR.git
cd InCar-ASR

python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e .
```

如果分支已合并到 `main`，把 `--branch agent/robust-asr-platform` 改成 `--branch main`。

这一步只安装 NumPy，不会下载模型和数据集。

## 3. 先验证输入资料

```bash
incar-asr validate-contract \
  --contract /path/to/model_contract.json \
  --require-artifacts

incar-asr validate-manifest \
  --manifest /path/to/test_manifest.jsonl
```

如果契约是 560 维 Paraformer，而要运行的是当前 C++ CLI，请停止并通知代码组。当前 C++ 路径要求 80 维 FBank、CTC logits、单输入、单输出和 float32 I/O。

## 4. CANN 和 NPU 环境

默认 CANN 路径是 `/usr/local/Ascend/ascend-toolkit/latest`。如实际路径不同，先修改 `modules/04_atlas_edge_deployment/scripts/env_setup.sh` 中的 `ASCEND_HOME`。

```bash
source modules/04_atlas_edge_deployment/scripts/env_setup.sh
npu-smi info
atc --version
```

判断：

- `npu-smi info` 必须能看到目标 NPU。
- `atc --version` 只在需要模型转换时必须可用。
- 如果脚本显示 `ATC=not found`，检查 CANN 安装路径。

## 5. 编译

```bash
cmake -S modules/04_atlas_edge_deployment \
  -B modules/04_atlas_edge_deployment/build \
  -DCMAKE_BUILD_TYPE=Release

cmake --build modules/04_atlas_edge_deployment/build \
  -j"$(nproc)"
```

主要产物：

```text
modules/04_atlas_edge_deployment/build/acl-hello
modules/04_atlas_edge_deployment/build/car-asr-cli
modules/04_atlas_edge_deployment/build/libcarasr.so
```

若 CMake 找不到 `acl/acl.h` 或 `libascendcl.so`，不要复制文件到系统目录。先确认 `ASCEND_HOME`，并把 CMake 的完整错误发给代码组。

## 6. NPU 最小链路

```bash
modules/04_atlas_edge_deployment/build/acl-hello --device 0
```

必须看到 `ALL CHECKS PASSED`。否则还未进入 ASR 问题，先处理驱动、固件、CANN 或设备权限。

## 7. ONNX 转 OM（已有 OM 时跳过）

先确认：

- ONNX 是单输入、单输出 CTC 模型。
- 输入名与模型一致，下面示例是 `speech`。
- 输入是 `[1,T,80]` float32。
- 输出是 `[1,T,V]` float32。
- SoC 型号与设备一致，不要只照抄示例。

转换示例：

```bash
modules/04_atlas_edge_deployment/scripts/atc_convert.sh \
  /path/to/model.onnx \
  speech \
  498 \
  Ascend310B1
```

参数依次是 ONNX、输入名、静态输入帧数、SoC。498 帧约对应 5 秒 10 ms 帧移。若业务语音更长，应增大帧数或在业务层切段。

ATC 允许内部把 FP32 算子转成 FP16，但当前 C++ CLI 要求模型外部 I/O 仍为 float32。CLI 初始化时会检查。

转换后：

```bash
sha256sum /path/to/model_fp16.om
ls -lh /path/to/model_fp16.om
```

把 SHA256 填入组内 artifact manifest。

## 8. 准备音频

CLI 只接收 PCM16、单声道、16000 Hz WAV。可用 ffmpeg 转换：

```bash
ffmpeg -i input.wav -ac 1 -ar 16000 -c:a pcm_s16le output_16k.wav
```

不要用 MP3 改扩展名冒充 WAV。

## 9. 单条识别

```bash
modules/04_atlas_edge_deployment/build/car-asr-cli \
  --model /path/to/model.om \
  --tokens /path/to/tokens.txt \
  --wav /path/to/output_16k.wav \
  --device 0 \
  --vad-mode 2 \
  --beam-size 1 \
  --json
```

stdout 最后一行应类似：

```json
{"text":"打开空调","inference_ms":12.3,"total_ms":28.6,"rtf":0.021,"sample_rate":16000,"device_id":0}
```

检查：

- `text` 不是乱码。
- 输出词表维数与 token 行数一致。
- 没有 `feature input truncated`；若出现，语音超过静态输入。
- `rtf < 1` 才表示端到端快于实时。

VAD 没检测到语音时，可先试 `--vad-mode 1` 或 `0`，并保留原始音频交给代码组，不要直接删除失败样本。

## 10. 正式批量测试

测试 manifest 示例位于 `examples/manifest.example.jsonl`。音频路径相对 manifest 解析。

```bash
./scripts/run_device_benchmark.sh \
  /path/to/test_manifest.jsonl \
  /path/to/model.om \
  /path/to/tokens.txt \
  device_report \
  modules/04_atlas_edge_deployment/build/car-asr-cli
```

脚本会：

1. 校验 manifest 和音频文件。
2. 记录设备工具版本及模型/token/CLI 的 SHA256。
3. 对含噪样本按指定 SNR 动态混噪。
4. 对每个样本调用 C++ CLI。
5. 生成真实指标和 bad cases。

## 11. 需要交回代码组的内容

必须交回：

```text
device_report/
├── device_info.json
├── results.jsonl
├── summary.json
└── report.md
```

另外保存：

- CMake 配置和编译完整日志。
- `acl-hello` 完整输出。
- 单条 golden sample 的 CLI 完整输出。
- ATC 命令和转换日志（如果在设备侧转换）。
- 出错样本的原始 WAV，单独放组内存储，不提交 Git。
- 实际测试场景：车速、窗户、空调风量、距离、麦克风位置。

不要只发截图或只抄一个平均延迟。代码组需要逐样本结果和 SHA256 才能复现。

## 12. 性能 profiling

在单条识别已正确后再做：

```bash
PROFILE_DIR="$PWD/device_profile" \
modules/04_atlas_edge_deployment/scripts/profile.sh \
  --model /path/to/model.om \
  --tokens /path/to/tokens.txt \
  --wav /path/to/output_16k.wav \
  --json
```

profiling 文件通常较大，不提交 Git；压缩后放组内文件存储并记录链接。

## 13. 常见故障

### `acl-hello` 失败

属于驱动/CANN/权限问题。先提供 `npu-smi info`、CANN 版本和错误码，不要调 ASR 参数。

### `This CTC runtime requires exactly one input and one output`

拿到的是多输入模型或完整 Paraformer，不符合当前 C++ contract。需要重新导出或扩展运行时。

### `requires float32 model I/O`

OM 外部 I/O 是 FP16/INT8。重新转换并保留 FP32 外部接口，或由代码组实现对应 dtype。

### token 是乱码或内容错位

确认 token 文件是 UTF-8、每行一个 token、行号从 0 开始，并核对 SHA256 和输出 V 维。

### `Failed to read WAV`

音频不是 PCM16/mono/16 kHz，按第 8 节转换。

### VAD 无语音

先确认波形不是全零；尝试更低 `--vad-mode`；提供音频和场景信息。不要把 VAD 失败记录为模型识别正确。

### 输入被截断

增大 ATC `input_frames`，或把长录音先用流式 VAD 切成短句。

### 批测“有效样本为 0”

查看 `results.jsonl` 中每条 `error`。程序故意不允许全失败却生成成功报告。
