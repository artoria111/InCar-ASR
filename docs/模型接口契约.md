# 模型接口契约

## 为什么必须有契约

ASR 模型能加载不等于能正确识别。FBank 的频谱定义、LFR、CMVN、输入 tensor 名、dtype、输出类型和 token 顺序只要有一项不一致，程序仍可能运行，但结果没有意义。

正式交接时，模型组必须提交：

1. `model_contract.json`
2. 模型文件的来源、SHA256、大小和许可证/使用范围
3. token 文件和 SHA256
4. 至少 10 条 golden audio 的参考文本
5. Python ONNX 输出和设备 OM 输出对比

## 两条现有路径

| 项目 | ONNX 参考示例 | Atlas C++ 示例 |
|---|---|---|
| 配置 | `model_contract.example.json` | `model_contract_atlas_ctc.example.json` |
| 前端维数 | 80×7 = 560 | 80 |
| LFR | m=7, n=6 | 无 |
| 解码 | Paraformer token logits | CTC logits |
| 输入数量 | 契约决定 | 1 |
| 输出数量 | 契约决定 | 1 |
| I/O dtype | float32/float16 输入 | float32 |
| 动态时间 | ONNX Runtime 支持 | 当前 C++ 使用静态 OM 缓冲区 |

不要把 560 维 Paraformer OM 直接交给固定 80 维的 C++ 程序。

## JSON 字段

- `version`：当前固定为 1。
- `model_name`：稳定名称和版本。
- `backend`：例如 `onnxruntime` 或 `ascendcl`。
- `model_path`、`tokens_path`：相对契约文件或绝对路径。
- `sample_rate`：必须与 frontend 一致。
- `input.features_name`：模型实际输入名。
- `input.lengths_name`：可选长度输入名。
- `input.shape`：`[B,T,D]`，动态维使用 `-1`。
- `input.dtype`：`float32` 或 `float16`。
- `output.logits_name`：token/logits 输出名。
- `output.lengths_name`：可选输出长度名。
- `decoder.type`：`ctc` 或 `paraformer`。
- `decoder.blank_id`：CTC blank id。
- `decoder.special_token_ids`：解码时跳过的 token。
- `frontend`：采样率、窗长、帧移、FFT、Mel、预加重、power/magnitude、LFR 和 CMVN。

## Atlas C++ 的严格要求

当前 `car-asr-cli` 初始化时会检查：

- 恰好一个输入和一个输出。
- 输入和输出都是 float32。
- 输入缓冲区可解释为 80 维 FBank。
- 输出 shape 是 `[1,T,V]` 或 `[T,V]`。
- token 文件行数和模型词表维数应一致。

短语音会补零到静态模型输入；过长语音会警告并截断。为避免截断，ATC 转换的 `input_frames` 应覆盖目标最大语音时长，或在业务层先切段。

## 数值一致性验收

同一条 golden WAV 建议保存并对比以下信息：

1. Python 提取的 FBank shape、均值、标准差和前 10 个值。
2. C++ 提取的相同摘要。
3. ONNX 输出 shape 和前若干 logits。
4. OM 输出 shape 和前若干 logits。
5. greedy token id 序列和最终文本。

至少满足：

- 前端 shape 完全一致。
- token 文件 SHA256 完全一致。
- 输出 shape 完全一致。
- 文本在 golden set 上一致。

若不一致，先从前端和 token 顺序排查，不能直接通过命令纠错掩盖模型接口错误。
